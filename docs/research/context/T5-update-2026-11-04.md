# T5 记录：中途追加 system 与工具声明

核对日期：2026-11-04。只在 Chat Completions 上各追加一种变化。不接 Engine，不写 Run。档案不改。获取模型列表里的 `system_prompt_update` 属于 Anthropic Messages，这次不引用。

## 方法

测试：`crates/engine-custom/tests/context_update.rs` 的 `mid_conversation_update_when_deepseek_client_response`。命令是 `cargo test -p fluxaxiom-engine-custom --test context_update mid_conversation_update_when_deepseek_client_response -- --ignored --exact --nocapture`。进程从 `.env` 读到 `DEEPSEEK_API_KEY` 后拨号，输出里没有密钥。

模型 `deepseek-flash`。`reasoning_effort` 为 `Low`，`max_tokens` 为 1024。两条探针都先发一段短对话。user 里有 1024 个「中」，用来让前缀长到可能命中缓存。第二次请求只多一处：system 探针在消息末尾追加一条 system；工具探针在工具列表末尾追加一个工具。其余消息不变，也不把第一次的 assistant 回复拼回去。

system 探针的第一条 system 要求单个词 `red`，追加的那条要求单个词 `blue`。正文去掉首尾空白并转成小写后恰好是 `blue` 记为遵循，恰好是 `red` 记为没有遵循，其他正文记为 `unclear`。工具探针的 user 点名 `pong`。第一次只声明 `ping`，第二次再声明 `pong`。响应里出现名为 `pong` 的调用记为遵循，否则记为没有遵循。不记录参数。

成功记为 `completed`。只记录 `prompt_tokens`、`prompt_cache_hit_tokens`、`prompt_cache_miss_tokens` 和是否遵循。某一段没有完成就停，这次没有发生。

## 结果

四次都完成。

| 探针 | 步骤 | prompt | hit | miss | 遵循 |
| --- | --- | ---: | ---: | ---: | --- |
| system | 第一次 | 1064 | 0 | 1064 | — |
| system | 追加 system | 1072 | 896 | 176 | yes |
| tool | 第一次 | 1300 | 0 | 1300 | — |
| tool | 追加工具 | 1325 | 0 | 1325 | yes |

追加 system 之后，正文是新增的那个词。同一条前缀的命中是 896。追加工具之后，模型调用了新工具。这次请求的命中是 0；第一次工具请求也是 0，所以看不出追加工具声明有没有打断一次已经存在的命中。

## 结论

Chat Completions 上，末尾追加的 system 被遵循，并且原前缀仍然命中。末尾追加的工具声明也被遵循。`system_update` 和 `tool_update` 这次不写进档案，可信度仍是「未知」。
