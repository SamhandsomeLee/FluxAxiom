# T4 记录：窗口与输出上限的文档核对

核对日期：2026-11-04。只重读当前文档，不调用 API，不改档案，也不改硬上限公式。

## 方法

核对这三页：

- Chat Completions：<https://api-docs.deepseek.com/zh-cn/api/create-chat-completion>
- 思考模式：<https://api-docs.deepseek.com/zh-cn/guides/thinking_mode>
- 获取模型列表：<https://api-docs.deepseek.com/zh-cn/api/list-models>

`max_tokens` 的说明指向模型与价格页 <https://api-docs.deepseek.com/zh-cn/quick_start/pricing>。这一页也打开了，只看它有没有写出窗口构成和思维链是否计入 `max_tokens`。价格数字不记入本记录。

上次文档观察是 ADR-020 的 2026-10-23。这次以当天页面为准，不沿用那次“文档没有写”的结论。

## 结果

获取模型列表把 `context_window` 写成：上下文窗口的 token 总容量，输入与输出 token 合计。同页样例里 `deepseek-flash` 的 `context_window` 是 1048576，`max_output_tokens` 是 393216。样例不是一次真实的 `GET /models`。

Chat Completions 对 `max_tokens` 写明：限制一次请求中模型生成 completion 的最大 token 数，范围是 1 到 384K（393216）。未设置时，非思考模式默认 8K，思考模式默认 64K，`reasoning_effort` 为 `max` 时为 128K。同一段还写：输入 token 和输出 token 的总长度受模型的上下文长度限制。

思考模式页说明思维链经 `reasoning_content` 返回，以及带 `tools` 时必须回传。它没有写上下文窗口，也没有写 `max_tokens` 是否计入思维链。

模型与价格页列出 `deepseek-flash` 的上下文长度 1M、输出长度最大 384K，版本是 DeepSeek-V4.1-Flash-1017。它没有写这 1M 是否已经包含输出，也没有写思维链是否计入 `max_tokens`。

Chat Completions 的用量里，`reasoning_tokens` 放在 `completion_tokens_details` 下，说明是“推理模型所产生的思维链 token 数量”，上一行把该对象称为 completion tokens 的详细信息。页面没有写思维链计入 `max_tokens`，也没有写 `reasoning_tokens` 与 `completion_tokens` 的加减关系。

## 结论

`window_counts_output` 有直接句子：上下文窗口合计输入与输出 token。取值仍是“是”。这次不改档案，可信度仍是「未知」。

`reasoning_in_output` 没有直接句子，保持未知。假设值“是”不动。近上限探测这次不做；若以后要做，只针对这个字段，并事先封顶次数。
