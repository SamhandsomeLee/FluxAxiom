# Progressive Hints · 分级提示

默认从 L1，用户可以直接要求任一级。

- **L1（原理）**：指出规则、失败机制或不变量，不展示可直接替换的生产实现。
- **L2（定位）**：点明相关表达式、类型、所有权关系或错误传播路径；真实行号需已经核对。
- **L3（支架）**：给最小可编译独立示例、伪代码或接口签名，并说明还有哪些部分由用户完成。
- **L4（完整参考）**：仅在用户明确要求完整答案时给出。必须解释核心取舍、适用边界和验证方法；默认只在对话里展示，不直接落文件。

切换机制：
1. 对于用户的“再具体一些”“没理解”等请求，升一级；不机械重复同一段解释。
2. 用户明确“给完整实现”可直接到 L4，但“写入仓库”需另外明确授权。
3. 诊断有多种合理解法时，优先讲影响，避免只给一个能通过编译的补丁。
4. 如果问题只是查清一行代码、一个语法点，不要求完整五阶段开发流程。
5. 每次提示只针对当前核心难点，避免同时附加大量无关的 Rust 知识点。
